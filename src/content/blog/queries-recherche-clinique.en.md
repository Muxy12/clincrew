In clinical research, a query is a request to clarify or correct a data point entered in the case report form. It is a central data-quality tool: each inconsistency detected leads to a query, then to a response from the site.

## Why queries?

A trial's data must be accurate, complete and consistent. When a value seems inconsistent (an impossible date, a missing data point, a discrepancy with the source document), nothing is erased: a query is opened so the site can check and correct if needed, keeping a trace of the change.

## Who raises them?

Queries come from two complementary sources:

- **Automatic**: generated by the [eCRF](/en/blog/crf-ecrf-cahier-d-observation)/EDC through programmed consistency checks.
- **Manual**: opened by the [data manager](/en/glossaire/data-manager) or the CRA, notably after [source data verification (SDV)](/en/glossaire/sdv).

## A query's cycle

Opening, site response, verification, then closure. As long as a query stays open, the data is not considered reliable. Query follow-up is an indicator of a site's data health.

## The CRA's role

The CRA helps limit queries upstream (by securing quality during [visits](/en/services/visites-de-monitoring)) and helps resolve them: explaining to the site what is expected and helping close open items before database lock.
